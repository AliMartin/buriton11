## Upgrade performed

1. Confirmed the actual local site and current official stable target,
   [Drupal 11.4.10](https://www.drupal.org/project/drupal/releases/11.4.10).
2. Added `.ddev/nginx/private-storage.conf`, denying direct HTTP access to
   `/private-files`, `/database` and `/tmp`, alongside the existing `/sync`
   denial. An **existing** private file, an export and a temporary file all
   return 403, before and after the DDEV restart. This does not replace Drupal's
   access controls on `/system/files` downloads.
3. Added the following inside the existing **DDEV-only** block in ignored
   `sites/default/settings.php`:

   ```php
   $config['automated_cron.settings']['interval'] = 0;
   ```

   This prevents automatic feed/content changes during comparison. It is a
   local settings override, not an exported configuration change. Mail remains
   routed through DDEV Mailpit. No full cron run or form submission was made.
4. Allowed the official `symfony/runtime` Composer plugin and changed all four
   root core requirements from `^10.6.19` to `~11.4.10`:
   `core-recommended`, `core-composer-scaffold`, `core-project-message` and
   `core-vendor-hardening`.
5. Reviewed `composer update --with-all-dependencies --dry-run`, enabled local
   maintenance mode and ran the actual update. The lock records 9 additions,
   32 upgrades and 1 removal, including Symfony 7.4 and the core-recommended
   dependencies. **No contributed Drupal project changed version.** Existing
   custom-theme sources and all four managed patches are retained.
6. Ran `drush updatedb --yes` and rebuilt caches. All planned updates completed;
   a subsequent update-status check reports none pending.
7. Reviewed the new core scaffold, including `index.php`, `update.php` and
   **`autoload_runtime.php`**. The latter selects Drupal's runtime and requires
   `vendor/autoload_runtime.php`, generated by the allowed runtime plugin.
   Include the root runtime scaffold when reviewing/deploying the source.
   Core scaffolding had appended ignore rules for root entry points; these were
   removed, and `extra.drupal-scaffold.gitignore` is now `false` so future builds
   preserve this project's reviewed root rules. All DDEV Traefik routes/TLS
   material are ignored, including copies bearing old project names.
8. Changed DDEV's project type to `drupal11` and restarted it. DDEV reported a
   router-count mismatch across the workstation's routes, but completed the
   restart; all recorded requests to this project's hostname succeeded.
9. Reviewed the private configuration export and copied the intended migrations
   into `sync`: **59 updated exports, 2 retired, 534 remaining**. No stale
   configuration import was run. Active/exported configuration now matches.
10. Returned maintenance mode to integer zero, rebuilt caches and verified the
    public site, private storage protection and local runtime settings.

The version constraints allow later 11.4 patches. For production, deploy the
tested lock with `composer install`; do not perform a fresh dependency solve
during cutover. Recheck the supported security patch before the rehearsal.

## Reviewed configuration migrations

These changes come from the core updates, rather than a theme redesign:

- Added core `search_node` and `search_help` modules; existing search pages now
  depend on their new provider modules. Core recreated the search view-mode
  metadata; public search was exercised successfully after the migration.
- Retired obsolete `field.settings` and `system.rss` exports.
- Converted block depth/page/pager settings to the new null/default forms and
  removed obsolete content-block settings.
- Moved CKEditor list `type` support to native list styles in the four editor
  configurations, removing the corresponding source-editing tag exceptions.
- Updated Views pager/table/RSS/dependency options and removed disabled
  remember-role entries. CSS/JS `gzip` keys become `compress`.
- The core permission migration adds **`rebuild node access permissions`** to
  the existing `website_editor` role. Review this intentional core-generated
  permission change during production access acceptance.

Form definitions, handlers/recipients, content, public/default/admin theme
selection and the retained contributed project versions were not changed.
The complete reviewed export diff is recorded with the evidence.
